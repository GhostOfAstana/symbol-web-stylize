# Текстовые подсказки из базового symbol-web

Помимо основного задания проект сохраняет функции базового `symbol-web`: автодополнение текста, выбор шрифта по правилам и творческие варианты текста. Они находятся в `internal/textai`; браузерный код — в `static/js/text-assist.js`.

| Запрос | Результат |
| --- | --- |
| `POST /api/suggest` | `{"suggestions":["hello!","hello World","~ hello ~"]}` |
| `POST /api/recommend-banner` | Рекомендуемый шрифт, русское объяснение и две альтернативы со сравнительными оценками |
| `POST /api/variations` | Четыре варианта текста с описаниями и подходящими шрифтами |

Тело каждого запроса — JSON `{"text":"hello"}` с `Content-Type: application/json`. Для подсказок и вариантов нужны хотя бы три символа; выбор шрифта работает с одним непустым символом. Верхний предел ввода — 4096 байт. Допускаются печатные ASCII-символы и переводы строк. Подсказки модели проверяются отдельно: от трёх до пяти уникальных однострочных вариантов, каждый короче 50 символов и пригоден для ASCII-генератора.

## Режимы работы

Если `LLM_BASE_URL` пуст, сервер работает в детерминированном демонстрационном режиме: никаких запросов к модели и ключей не требуется. Из одинакового текста получаются одинаковые продолжения. Выбор шрифта всегда основан на правилах и никогда не обращается к сети.

Для настоящей Ollama задайте переменные перед запуском:

```bash
export LLM_BASE_URL=http://localhost:11434
export LLM_MODEL=имя_доступной_модели
export LLM_PROVIDER=ollama
go run ./cmd/server
```

Модель должна быть заранее доступна на выбранном сервере. Приложение само ничего не устанавливает и не загружает. Для совместимого API OpenAI задайте `LLM_PROVIDER=openai`; `LLM_BASE_URL` может оканчиваться на `/v1`. Ключ, если провайдер его требует, передаётся через `LLM_API_KEY` и остаётся на сервере. `LLM_BASE_URL` и `LLM_MODEL` всегда читаются из окружения. Настроенный адрес без модели считается ошибкой конфигурации, которую сервер сообщает при запуске.

`LLM_PROVIDER` — основное имя настройки протокола. Старое имя `LLM_PROTOCOL` поддерживается как запасное: оно используется, если `LLM_PROVIDER` не задано. Если обе переменные заданы и противоречат друг другу, сервер сообщает об ошибке конфигурации при запуске. Так палитры и текстовые подсказки используют один и тот же выбранный протокол.

Для Ollama сервер добавляет к базовому адресу `/api/generate`; если адрес уже заканчивается на `/api`, добавляется только `/generate`. Для OpenAI добавляется `/v1/chat/completions` без повторного `/v1`. Допустим завершающий слеш базового адреса. Таймаут запроса к модели — десять секунд. Ответ ограничен 64 КиБ. Перенаправления запрещены, чтобы ключ авторизации не уходил на другой адрес. Одновременно выполняются не более восьми запросов к модели; при перегрузке API возвращает понятную ошибку.

Недоступная модель или таймаут дают `503`; некорректное содержимое ответа модели — `500`; неправильный пользовательский JSON или текст — `400`; неправильный HTTP-метод — `405` с заголовком `Allow: POST`. Ошибки модели не мешают обычному созданию ASCII-баннеров. Сообщение сервиса из недоверенного ответа не показывается пользователю и не исполняется браузером.

## Правила выбора шрифта

Правила применяются по порядку:

1. Все буквы заглавные либо текст не длиннее шести символов — `shadow`.
2. Иначе текст длиннее двенадцати символов — `standard`.
3. Остальной короткий текст со смешанным регистром — `thinkertoy`.

Если букв нет, условие «все буквы заглавные» ложно: например, `123456789` выбирает `thinkertoy`. Это устраняет ошибочное применение правила к пустому набору букв. Оценки альтернатив показывают порядок запасных вариантов, а не вероятность нейросети.

## Кэш и браузер

Успешные подсказки и варианты сохраняются в оперативной памяти на пять минут. Ключ включает тип операции и текст. Не более 256 записей; просроченные записи удаляются, при заполнении вытесняется самая старая. Ошибки не кэшируются. Доступ к кэшу защищён mutex; перезапуск сервера его очищает.

После ввода браузер ждёт 300 мс и отправляет запрос подсказок. Новый ввод отменяет предыдущий запрос; устаревший ответ не заменяет свежие варианты. Выбор варианта заполняет текст, а для творческого варианта — ещё и шрифт. Содержимое модели вставляется через `textContent`, а не через `innerHTML`.

## Ответы для аудита

**Что здесь является LLM, а что правилами?** Продолжения и варианты текста могут генерироваться настоящей моделью. Выбор шрифта — детерминированная функция над длиной и регистром текста. Mock — отдельный нормальный режим без сети, а не скрытая подмена неудачного сетевого ответа.

**Как убедиться, что API действительно вызывает модель?** Запустить с адресом и именем модели, проверить сетевой запрос на стороне сервера модели. В unit-тестах локальный `httptest.Server` проверяет путь запроса, модель из конфигурации, заголовок авторизации и формат тела; второе одинаковое обращение обслуживается из кэша.

**Почему ответ модели проверяется?** Указание в prompt не гарантирует формат результата. Сервер отдельно проверяет JSON, количество вариантов, допустимые ASCII-символы, длину, уникальность и имя шрифта.

**Что случится при недоступной модели?** В течение не более десяти секунд запрос завершится с `503` и русским сообщением; основной генератор продолжит работать. Уже закэшированный успешный результат доступен до истечения пяти минут.

**Зачем одновременно таймаут клиента и context?** `http.Client.Timeout` ограничивает обмен целиком, а контекст прекращает работу также при отмене исходного HTTP-запроса. В обоих случаях не остаётся бесконечно ожидающего обращения к модели.

**Как проверялась отказоустойчивость?** Тесты покрывают mock, оба протокола, неверный JSON, повторяющиеся и слишком длинные ответы, превышение размера, `503`, таймаут, отмену контекста, протухание и предел кэша, конкурентные запросы. Проверка `-race` ищет гонки данных.
