# Как воспроизвести проверку

## Автоматические проверки

```sh
go test -race -count=1 ./...
go vet ./...
node --test static/js/palette.test.cjs
```

`TestConcurrentHTTPStress` запускает 100 независимых сценариев запросов палитры и генерации. `TestBackendFailures` проверяет плохой статус, испорченный JSON, слишком большой ответ, перенаправление, отмену запроса и закрытый порт. Тестовый сервер тайм-аута сам завершается, поэтому проверка не оставляет зависших обработчиков.

```sh
go test ./internal/ai -run=^$ -fuzz=FuzzContrast -fuzztime=5s
go test ./internal/ascii -run=^$ -fuzz=FuzzGenerate -fuzztime=5s
```

Фаззинг генерирует новые входы. Количество проверенных случаев зависит от процессора и длительности; само наличие команды в инструкции не означает, что она запускалась.

## Интерфейс

1. Запустите сервер без LLM-переменных, откройте страницу на ширинах 375, 768 и 1920 пикселей.
2. Убедитесь, что вся страница помещается по ширине. Горизонтальная прокрутка допустима внутри области баннера.
3. Пройдите Tab/Shift+Tab и нажмите Enter на кнопках. Фокус должен быть виден на фоне любой темы.
4. Создайте `Hello` тремя шрифтами. Создайте многострочный текст. Скопируйте рисунок; при запрете буфера обмена должна появиться инструкция.
5. Получите палитры. Должны появиться три карточки с пятью свотчами, пояснением, настроением и одним рекомендованным вариантом.
6. Примените вариант и перезагрузите страницу. Выбранная тема должна сохраниться.
7. Примените три палитры. Индикатор памяти покажет средний тон и светлоту; следующий POST содержит `preference`. Ответ mock изменит основные цвета.
8. Сохраните несколько вариантов. Создайте свою палитру с одинаковыми фоном и текстом: текст будет автоматически исправлен.
9. Очистите память, сбросьте тему, удалите сохранённые варианты. Эти действия независимы.
10. В DevTools испортите `symbol.theme`, `symbol.saved`, `symbol.history`. После перезагрузки страница должна работать. Повторите с заблокированным хранилищем.
11. Укажите неработающий LLM-адрес и модель, перезапустите сервер. Запрос палитры даст 503 и понятное сообщение; генерация останется доступной.
12. С действующим LLM проверьте получение трёх палитр. Просмотрите запрос к API и убедитесь, что модель берётся из конфигурации.

## Что не следует выдавать за проверку

Тесты с `httptest` проверяют контракт и ошибки интеграции, но не подключение к вашему конкретному Ollama. Успешная проверка Chromium не доказывает ручную проверку Safari, Firefox и Edge. Работа с устройством шириной 375 пикселей в DevTools не равна тесту на физическом телефоне.

## Фактически выполнено 25 октября 2026 года

`go test -race -count=1 ./...`, `go vet ./...` и пять тестов `node --test static/js/palette.test.cjs` завершились успешно. Пятисекундный `FuzzContrast` проверил 430984 входа без ошибки; число входов приведено как результат конкретного запуска, а не как обещание скорости.

Браузерный сценарий на уже установленном Chrome 155.0.8059.85 прошёл на ширинах 375, 768 и 1920. Проверены отсутствие переполнения страницы, отправка формы, три палитры, применение, память после трёх выборов, отправка `preference`, восстановление и повреждение `localStorage`, сохранённая тема, тёмная тема/сброс и видимый фокус. Скриншоты узкой и широкой страницы просмотрены. Необработанных ошибок JavaScript не обнаружено. Браузер и пакеты при проверке не устанавливались.

Исходник сценария: `scripts/browser-smoke.cjs`. Нужен уже доступный Playwright и браузер:

```sh
node scripts/browser-smoke.cjs http://localhost:8080
```

Необязательные аргументы: существующая папка для снимков, путь к модулю Playwright, путь к исполняемому файлу браузера. Скрипт ничего не загружает и не устанавливает.

После независимого ревью повторно выполнены проверки Go с `-race`, `go vet` и тесты JavaScript. Дополнительный браузерный сценарий подтвердил создание своей палитры с автоматическим исправлением контраста, отклонение запоздавшего ответа после изменения текста и понятную обработку HTTP 503 с восстановлением кнопки.
